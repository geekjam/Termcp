# 可移植主机配置导出格式 v1

未设置文件密码时沿用 `[[connections]]` TOML。设置密码时使用以下二进制信封；格式只用于用户主动导出，不与本地 `events.enc` 或数据主密钥混用。
实现：`internal/sshconfig/transfer.go`。所有整数为小端序。

| 字节位置 | 内容 |
| --- | --- |
| 0–7 | Magic：`TCPCFG\r\n` |
| 8–9 | 版本 1 |
| 10–11 | 保留，必须为零 |
| 12–15 | Argon2id Time |
| 16–19 | Argon2id Memory，KiB |
| 20 | Argon2id Threads |
| 21–23 | 保留，必须为零 |
| 24–39 | 随机 16 字节 salt |
| 40–63 | 随机 24 字节 XChaCha20-Poly1305 nonce |
| 64–71 | 明文 TOML 字节数 |
| 72 起 | 密文 TOML + 16 字节认证标签 |

Argon2id 从用户文件密码派生 32 字节密钥；默认成本与存储密码一致：64 MiB、Time=3、Threads=1。72 字节完整头部作为 AEAD AAD，头部与密文一并认证。每次导出重新生成 salt 和 nonce，同一个密码不会产生相同文件。

解密前校验 Magic、版本、保留字段、明文长度与文件长度一致性，明文上限 16 MiB。v1 接受的成本范围为 Memory=8–64 MiB、Time=1–3、Threads=1，超过范围立即拒绝，不运行 KDF。生产写出采用默认成本；测试使用低成本覆盖相同格式。文件总大小上限为 16 MiB + 88 字节。

该格式不包含原实例数据主密钥、系统托管引用或存储密码。完整解密认证后才调用 TOML 批量校验及导入，不能逐条解密后提前写入配置。错误密码与密文损坏共用认证失败错误，不能把认证失败当作明文重新解析。
文件格式由内容识别，重命名不会改变保护方式；向明文文件提供解密密码会明确拒绝，避免误以为文件已经加密。

导入的 multipart 限制为一个 `file` 和可选一个 `password`，重复/未知字段拒绝。服务端用 MultipartReader 流式读取到有界内存，不使用会产生磁盘暂存的 ParseMultipartForm。HTTP 接入按单任务互斥限制大文件和 KDF 并发，并沿用存储密码提交的传输保护规则。

## 旧导出格式兼容

保留 `X-Termcp-Password` 头接口产生的 `TERMCP-ENC 1` 文本信封（PBKDF2-HMAC-SHA256、AES-256-GCM）。新的 Web UI/multipart 导入按文件内容识别此格式，使用对应文件密码完成认证后再批量导入；缺少或错误密码不会写入部分主机。两种导出格式都不包含本地数据主密钥，临时主机在两种导出路径中均被排除。
