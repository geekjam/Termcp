# 本地落盘清单与纯文件加密存储设计

状态：开发分支已接入加密文件、事件日志、密码 API/Web UI、启动门禁及可续迁的历史转换。服务在解锁、迁移和恢复完成前不建立业务图；提交后的存储只读密文。系统托管支持 Windows DPAPI、macOS Keychain 和 Linux Secret Service；常规单元测试使用替身，独立三系统 CI 使用隔离真实后端验证跨进程解锁、服务重启及凭据丢失/损坏，见 [测试说明](../agents/testing.md#native-system-key-stores)。平台执行结果仍以对应 CI 和真实部署验证为准。此文包含原格式盘点及新格式的设计边界，不代表已发布版本。

底层格式、接口边界与验证范围见 [`encrypted-file-format.md`](encrypted-file-format.md)。

## 旧格式落盘范围与迁移输入

范围为本仓库的 Go 服务端与 Web UI，不包括独立 npm/GUI 仓库的安装产物。
数据根目录按 `--data-dir`、`TERMCP_DATA_DIR`、`~/.termcp` 的顺序解析。
下面是旧版代码会创建的文件类型，也是迁移的盘点范围；不是对用户实际配置或历史内容的扫描。

### 固定持久化路径：10 种

路径均相对数据根目录，按功能使用情况创建，并非每次启动都会全部出现。

| 路径 | 当前内容 | 当前写入权限（POSIX） | 加密建议 |
| --- | --- | --- | --- |
| `ssh_configs/<name>/config.toml` | 持久主机的地址、用户、密码、内联私钥、私钥口令、带认证信息的代理 URL、递归跳板机配置 | `0600` | 凭据必须加密或交由系统秘密存储；建议整个配置加密 |
| `ssh_configs/.internal/config.toml` | 内置主机的可选覆盖配置，如默认 shell、审批设置 | `0600` | 纳入统一配置加密；即使没有凭据，也可能含敏感命令参数 |
| `sessions/<session_id>/manifest.json` | 会话名称、启动命令与参数、配置名称、状态、时间、审批设置等 | `0644` | 建议默认加密，命令和参数可能直接含秘密 |
| `sessions/<session_id>/<shell_id>/manifest.json` | shell 名称、编号、模式、状态、时间、终端尺寸和退出码 | `0644` | 建议默认加密，保护历史元数据 |
| `sessions/<session_id>/<shell_id>/log.bin` | 原始终端输出字节，包括终端回显、stdout/stderr | `0644` | 建议默认加密，可能包含凭据、文件内容和个人信息；二进制格式不等于加密 |
| `sessions/<session_id>/<shell_id>/log.jsonl` | 时间、字节偏移、输出/输入来源和审批标记；没有正文 | `0644` | 建议加密，保护活动时间和操作规律 |
| `sessions/<session_id>/<shell_id>/log.lines` | 换行位置的二进制偏移索引 | `0644` | 建议随历史一起加密 |
| `sessions/<session_id>/<shell_id>/log.stdio` | stdout/stderr 来源切换的二进制偏移索引 | `0644` | 建议随历史一起加密 |
| `extensions/<name>/config.toml` | 扩展模板的目标、命令、路径和 HTTP 认证头 | `0600` | 整体加密为同目录 `config.enc`，旧模板纳入迁移 |
| `termcp.log` | daemon 的 stdout/stderr，包括运行诊断、错误以及 debug 级 MCP 参数和返回预览 | `0600` | 先减少和脱敏记录；需要保留敏感诊断时加密保存 |

扩展模板每个名称占一个配置文件；加密运行时只读写 `config.enc`，不回退读取旧 TOML。模板迁移保留未知字段，已有加密存储的新增旧模板采用追加迁移，保持主机配置与历史。扩展协调器在解锁和迁移后启动，关闭时先停止协调器，再关闭会话和存储。

通常一个会话有 1 个会话 manifest，每个 shell 最多有 5 个文件；每个持久主机有 1 个配置文件。
daemon 日志另占 1 个文件，内置配置覆盖文件按需生成。
旧文件内容没有应用层加密。新建存储目录通常使用 `0700`，但已有目录的权限不会因此自动收紧；Windows 需要单独考虑 ACL。

当前输入路径只追加来源/提交标记，输入正文经终端回显进入输出日志，不单独复制原始 stdin。
因此不能笼统认为每次密码输入都会被记录，但回显的命令、程序打印的秘密和会话启动参数仍会落盘。
`session_terminate` 和进程退出保留历史，删除会话才移除其目录；当前没有历史保留期限或日志轮转策略。

### 临时文件：6 类

| 路径或模式 | 内容与生命周期 | 处理原则 |
| --- | --- | --- |
| 数据根目录下 `.write-probe` | 空的写权限探针，正常启动流程立即删除 | 无需加密 |
| 会话/shell 目录下 `.tmp-*` | manifest 原子替换的完整副本，成功后改名；崩溃可能遗留 | 必须从第一次写入起就是密文 |
| 扩展模板目录下 `.tmp-ext-*` | 旧版模板的原子替换副本，可能包含认证头 | 纳入加密备份与明文清理，新写入使用密文临时文件 |
| SSH 配置目录下 `.tmp-cfg-*` | 配置原子替换副本，成功后改名；异常可能遗留 | 与最终配置使用相同的加密要求 |
| 系统临时目录下 `termcp-known_hosts-*` | 主机公钥与地址，解析后删除 | 公钥不需要保密；限制权限、及时清理，避免泄漏主机清单 |
| 系统临时目录下 `multipart-*` | 大 multipart 上传可能由 Go 标准库暂存文件内容；普通 HTTP 请求结束会清理 | 内容敏感性与上传文件相同；优先使用不经明文临时文件的流式上传 |

### 导出、传输与浏览器

- 手动导出的 `termcp-connections.toml` 包含持久主机的完整凭据，属于敏感副本；导出时可选择独立文件密码，加密为 `.toml.enc`，两次密码均留空则保持明文 TOML。导入支持对应密码接口，文件先完整认证再导入，不依赖原实例主密钥。临时主机不进入导出结果，显式按名称请求也不例外。Web UI 对包含临时主机的导出选择给出提示；REST 混合选择只导出持久主机。
- SFTP `mode=file` 的 `local_path`、本地文件上传目标以及浏览器下载目录由调用方决定，内容保持用户所需的原始格式。这些是用户文件，不能未经业务约定透明改成 Termcp 私有密文格式。
- 浏览器 localStorage 保存语言、主题、布局和折叠状态，通常不需要加密。`termcp_token` cookie 则携带认证凭据，由浏览器管理，不在数据目录中；`HttpOnly` 不代表应用层加密。
- HTTP token/hash 由参数或环境传入，服务端不会专门写一个认证配置文件。当前 `auth-hash` 字符串本身也能通过认证，必须按可直接使用的凭据保护，不能当成可公开的校验摘要。
- 内置 SSH 服务的主机私钥和一次性连接凭据在内存中生成，没有独立私钥文件；临时主机的配置也仅保存在内存。临时主机规则约束主机配置，关联会话的历史是否保留是独立策略。
- `assets/` 和 `themes/` 是用户提供的静态资源目录，服务端只读取，不自动解包写出；默认位置不随 `--data-dir` 改变。本机 shell 自身的历史及命令创建的其他文件不属于 Termcp 的固定存储清单。

## 目标架构

采用 `os.File`、独立 AEAD 记录、追加日志和可重建索引，不引入 SQLite、其他数据库、FUSE、Afero 或 SIO。
职责分为 KeyManager、EncryptedFS、SessionRecorder 和 FileIndexer；AEAD 封装只执行一次，Recorder 负责业务事件编码，Indexer 负责历史查询。

沿用现有 session/shell 层级，避免把同一个会话中的多个 shell 混为一个字节坐标系：

```text
<data-dir>/
  .store.lock
  store.enc
  keys/master.key
  config/hosts.enc
  extensions/<name>/config.enc           # 按模板身份认证的原始 TOML
  sessions/<session_id>/
    meta.enc
    <shell_id>/
      meta.enc
      events.enc
      events.idx.enc
      .legacy-<migration_id>/*.enc        # 归属此 shell 的迁移副本（如有）
    .legacy-<migration_id>/*.enc          # 归属此 session 的迁移副本（如有）
  diagnostics/legacy-<migration_id>/     # 旧诊断日志和其他遗留副本
  termcp.log                            # 新版本仅记录脱敏运行诊断
  .migration/                           # 仅迁移期间存在
    active/state.enc                    # 加密的可续迁任务清单
    <migration_id>/staging/              # 只有密文目标文件
```

`.store.lock` 是跨进程排他访问的锁文件，不含秘密；锁由操作系统持有，不能通过文件是否存在或文件年龄判断占用状态。
`store.enc` 是经过认证加密的格式版本、活动数据代际和迁移提交标记，不保存一份冗余的会话列表。
它控制新旧格式的读取选择，不依靠是否存在某个 `.enc` 文件猜测迁移已经成功。
`master.key` 保存被 KEK 认证加密封装的随机主密钥以及 key slot 元数据。
`hosts.enc` 只包含持久配置和内置配置覆盖，不包含临时主机。
`events.enc` 是权威记录，索引可以删除、校验失败后丢弃并重建，不能反过来决定历史内容。
历史相关的事件、索引与元数据默认全部加密；目录中的不透明 ID、文件大小和文件系统时间仍可能暴露。

### 与现有目录的逐项对比

旧格式的目录如下，静态资源目录另列：

```text
<data-dir>/
  ssh_configs/
    <name>/config.toml
    .internal/config.toml               # 可选的内置配置覆盖
  sessions/<session_id>/
    manifest.json
    <shell_id>/
      manifest.json
      log.bin
      log.jsonl
      log.lines
      log.stdio
  termcp.log                           # daemon 模式

~/.termcp/assets/                      # 默认位置，可单独覆盖
~/.termcp/themes/                      # 与 data-dir 无关
```

| 当前文件 | 目标位置 | 变化及迁移要求 |
| --- | --- | --- |
| `ssh_configs/<name>/config.toml` | `config/hosts.enc` | 多个主机文件合并为一个加密容器；保留主机名称、跳板链、凭据、默认 shell 与审批默认值 |
| `ssh_configs/.internal/config.toml` | `config/hosts.enc` 中的内置配置覆盖 | 与持久远程主机分开标记；缺少覆盖文件时继续使用内置默认值 |
| `sessions/<sid>/manifest.json` | `sessions/<sid>/meta.enc` | 保留会话 ID、配置引用、名称、命令参数、时间及审批设置 |
| `sessions/<sid>/<shid>/manifest.json` | 同目录 `meta.enc` | 保留 shell ID、编号和元数据；不能因目录转换重新编号 |
| `log.bin` | 同目录 `events.enc` 中的 Output 事件 | 所有输出字节保持一致；改成有认证边界的记录，不是简单更名 |
| `log.jsonl` | `events.enc` 中的来源/审批/输出状态事件 | 原有标记是时间及操作归属的唯一来源，必须转入权威事件日志 |
| `log.lines` | `events.idx.enc` 中的行定位信息 | 直接从输出中的换行重建，不盲信旧索引 |
| `log.stdio` | Output 事件的流来源，及 `events.idx.enc` 中的查询索引 | 先保留旧文件提供的 stdout/stderr 分类，再生成新索引；不能仅从输出正文推导 |
| 无 | `keys/master.key`、`store.enc`、`.store.lock` | 新增密钥封装、格式切换和排他访问机制 |
| `termcp.log` | 按需转入 `diagnostics/legacy-<migration_id>.enc` | 旧诊断可能含秘密，不能遗漏在迁移范围外；新运行日志单独执行脱敏策略 |
| 无 | `.migration/<migration_id>/state.enc` 和 `staging/` | 新增可中断、可验证的迁移进度；临时目录也只写密文 |

会话层级不变：每个会话仍然有自己的元数据，每个 shell 仍然独立录制。
每个 shell 的常规文件由 5 个变为 3 个，具有 H 个 shell 的会话由 `1 + 5H` 个变为 `1 + 3H` 个。
配置合并、密钥文件和迁移控制文件要另外计算，不能把整体变化简单描述为“9 种路径变成 6 种”。
配置集中到 `hosts.enc` 是本方案的组织选择，并不是文件加密所必需；它意味着单主机更新也需要原子替换该容器。
`assets/`、`themes/`、浏览器状态和用户指定的文件传输目标不搬入加密存储目录。

用户提供的原始示意把 `events.enc` 放在 session 目录下；这里保留 `<shell_id>` 层，以兼容当前的多 shell 模型。
现行文档的“offset 等于 `log.bin` 物理位置”只适用于旧格式。新格式保留相同的公开输出偏移，但内部必须转换为密文记录位置。

### 加密记录与索引

使用 `chacha20poly1305.NewX`，每条记录使用 `crypto/rand` 生成新的 24 字节 nonce。
配置、日志、索引使用带用途标签及文件唯一标识的 HKDF 上下文派生不同密钥。
会话、shell、文件代际均需绑定到密钥派生或 AAD；原子替换创建新的文件 ID，防止跨文件替换。

公开记录头仅保留解析所需的有界长度、版本和 nonce 等信息，并纳入 AAD。
时间、事件类型、逻辑偏移及业务元数据放入密文内，再验证序号和偏移连续性。
**AAD 提供认证，不提供保密。** 仅加密索引、却把上述字段留在公开记录头中，仍会泄漏活动规律。
解析器在申请内存、解密或运行密码 KDF 前必须先检查长度和参数上限。

事件至少保留 Output（含 stdout/stderr 来源）、输入来源标记、审批标记和 Resize。
默认不新增原始 stdin 录制；未来如增加，需要单独明确开启规则。
只有 Output 正文字节推进公开历史字节偏移，Resize 和审批等零正文事件只推进事件序号。
时间戳继续遵循项目的 Unix 毫秒约定；如增加内部相对时间，需要明确转换，不能改变现有 REST/MCP 字段单位。

EncryptedFS 的明文文件视图和 SessionHistory 的输出视图分开：前者读取解密后的业务记录编码，后者过滤事件头及非输出事件。
不能直接把事件文件的明文偏移当成 `shell_output` 的输出字节偏移。
底层提供受限的记录遍历与位置定位能力给 Indexer，业务调用方只见 `ReadAt`、`Seek` 和明文输出大小。
第一版不提供公开的 `WriteAt` 或 `Truncate`，恢复截断仅由内部恢复流程执行。

每个 shell 的稀疏索引记录逻辑输出偏移、物理记录位置、事件序号和时间，并保留按行读取以及 stdout/stderr 分类所需的信息。
随机读先定位记录，再读取、认证、解密并裁取目标范围；跨记录读取必须循环拼接。
输出偏移与行号语义保持不变，不影响活会话、DEAD 会话、WebSocket、MCP 和 REST 的现有读取方式。
恢复 vim/top 等终端画面仍需重放控制序列和 Resize，普通字节 Seek 不等于屏幕快照。

### 写入、持久化与恢复

沿用现有每个存储实例单写入者的思路，协调追加、删除、关闭和恢复。
仅完整写出且认证格式完整的记录才向并发读者发布；发生部分写入后停止该文件的追加，先恢复再继续。
区分可读末尾、已执行 Sync 的末尾与索引检查点，不能把 `Write` 成功描述为断电后必然可恢复。
`Append` 返回的偏移也不代表已完成持久化；需要强确认的调用方必须等待 `Sync` 成功。

平衡模式可从每 1 秒或累计 256 KiB 执行 Sync 开始调优，任一条件满足即触发。
提供显式 Sync 和正常关闭时的错误返回，不承诺断电时固定最多丢失 1 秒。
小文件原子替换按密文临时文件写入、文件 Sync、关闭、原子发布和平台支持的目录持久化实现；Windows 使用经过验证的替换及共享冲突处理。

解锁后扫描并认证日志，从有效记录重建索引；索引丢失、损坏或超前不应破坏权威日志。
格式有效且长度受限、在 EOF 缺失字节的末尾记录仅作为未完成尾部候选；保留原始密文，按明确恢复策略处理。
不能仅凭 EOF 判断一定是崩溃，也不能发现任意认证失败就截断。
完整记录认证失败、序号/偏移断裂或中部损坏必须报告并停止自动修复，不能跳过坏记录继续拼接。
历史会话继续按现有语义恢复为 DEAD，不自动重连已消失的进程；底层文件恢复后的继续追加能力单独测试。
只有外部可信检查点或远程审计机制才能补充对完整尾部删除、整套文件回滚的检测。

### 密钥管理和启动解锁

KeyProvider 支持 Windows DPAPI、macOS Keychain、Linux Desktop Secret Service、容器 ENV 随机 KEK，以及 Web UI 密码经 Argon2id 派生 KEK。
默认自动使用系统托管，首次启动无需输入密码；非空 ENV KEK 优先。容器、无桌面的 Linux 或系统密钥服务不可用时，应配置 ENV 以便无人值守，也可手动使用密码，不能回退到明文。
密码 slot 保存随机 salt 和有界 KDF 参数；主密钥丢失、解锁失败或封装文件损坏时禁止静默生成新主密钥覆盖旧数据。
KEK 不与密文放在同一数据目录中，HTTP 认证凭据与存储解锁密钥分开。

普通启动状态为 LOCKED → RECOVERING → READY；发现旧格式时，在解锁后进入 MIGRATING，提交迁移后再执行恢复并进入 READY。
LOCKED/MIGRATING 只开放必要的静态界面、健康检查、初始化、认证、解锁及迁移进度接口，不能启动 session/MCP 操作或继续向旧历史写入。
Web UI 解锁应经过认证并限制尝试频率；远程解锁使用 HTTPS，密码不进入 URL、日志或浏览器持久存储。
Web UI 可保存自动或手动解锁方式，选择与主密钥封装单文件原子发布；手动方式移除自动 slot，后续每次重启输入主密码，且手动解锁后不自动托管。切换方式验证当前密码；首次手动方式要求新密码确认。运行期间不提供主动锁定，浏览器退出登录不锁定全局存储。
KEK 轮换通过重封装主密钥实现；主密钥/数据密钥轮换另有版本和迁移流程，不能混为一项操作。

用户在 Web UI 中自定义的是**主密码**，不是直接输入数据主密钥或 Base64 随机密钥。
主密码可选。首次设置提交两次相同的新密码；已由系统/ENV 解锁的存储追加密码 slot 并保留原数据主密钥与自动解锁 slot；未初始化时才生成随机数据主密钥。密码经 Argon2id 派生 KEK 后封装。已有仅密码存储成功解锁一次后可自动建立系统/ENV 托管。
修改时必须提交当前主密码、新主密码和确认新主密码；即使存储已解锁，后端也要重新验证当前密码，并独立核对新密码确认值。
该操作仅替换 password key slot，不重加密历史，也不改变其他已配置的 ENV/系统托管 slot。
接口只有在密钥文件原子替换及持久化确认成功后才能报告成功；替换前失败时保持原密码有效。
替换已发生但目录同步失败时返回明确的持久化未确认状态，不能把它当作成功或简单恢复成旧内存状态。
已注册的 REST 字段和 Web UI 行为见 [`storage-password-api.md`](storage-password-api.md)，部署配置见 [`../encrypted-storage.md`](../encrypted-storage.md)。

## 历史数据迁移

第一版采用停写后的启动迁移，不做明文/密文双写或运行中的热迁移。
迁移必须能够重复执行、从中断处恢复，并在验证完成前保留原始数据。
新格式的迁移能力属于第一版交付条件，不能等加密功能上线后再补。

### 用户提示与升级告知

迁移提示是第一版功能的一部分，不能仅在开发文档里说明。首次启用迁移的版本必须同时提供 Release 升级须知和实际运行时提示。
提示负责说明状态及用户需要采取的动作，不额外要求无人值守部署反复确认；需要密码解锁时才等待解锁输入。

| 时机 | 必须告知的内容 |
| --- | --- |
| 升级前的 Release 页面 | 新版本首次启动会迁移旧文件；迁移范围；停止旧进程、备份和额外磁盘空间要求；旧版不能直接打开迁移后的目录 |
| 启动检测到旧格式 | 已发现旧版持久化文件；密钥设置/解锁完成后将开始迁移；迁移期间会话与数据接口暂不可用 |
| 正在迁移或续迁 | 当前阶段、已完成/总会话或 shell 数、已处理字节数；续迁需说明正在恢复已有进度，不能伪装成全新空存储 |
| 正常完成 | 历史迁移及验证已完成，服务可用，旧会话以 DEAD 状态查看；只有清理完成后才说明旧明文已清理 |
| 转换或验证失败 | 失败阶段、可理解的原因和下一步操作；提交前失败时说明旧源保留，处理问题后可续迁 |
| 新格式提交成功但清理失败 | 显式提示 `CLEANUP_PENDING`：仍有旧明文残留，不能显示“所有数据已加密” |

首次提示的基准文案为：

> 检测到旧版持久化文件。新版本将在完成密钥设置或解锁后，将主机配置和会话历史迁移为加密存储。迁移期间服务暂不可用；请确保旧版本进程已停止，并已备份数据目录。

Web UI 在启动页持续展示迁移状态和进度，不使用会自动消失的 toast 作为唯一提示。
前台 CLI 与 daemon 启动入口也必须告知迁移开始、续迁、失败和完成；后台日志保留相同的阶段摘要。
CLI 人类提示写入 stderr，MCP stdio 的 stdout 继续只承载协议消息；非 READY 请求返回可识别的存储状态，不能只表现为超时或空历史。
进度在阶段变化时及时更新，字节进度适度节流；未完成盘点时只显示阶段或已处理数量，不编造百分比、剩余时长或持久性保证。
提示与日志不包含密码、密钥、原始命令输出或主机凭据；UI 文案纳入既有三语言词表。
没有旧数据的初始化和已经完成迁移后的正常重启，不重复显示“将迁移旧文件”。

发布文案草稿见 [`encrypted-storage-migration.md`](../release-notes/encrypted-storage-migration.md)。
对应版本的 `CHANGELOG.md` 开头必须包含升级须知，GitHub Release 必须带上该版本的已审核正文，而不是仅依赖自动生成的 PR 列表。
只有实际实现并验证迁移的版本才能使用“本版本会迁移旧文件”的发布文案；当前草案不能被当成已经上线的行为。

### 格式识别与提交边界

| 磁盘状态 | 新版本行为 |
| --- | --- |
| 没有旧数据，也没有新格式或迁移痕迹 | 初始化新存储 |
| 只有旧 TOML/manifest/log 文件 | 建立密钥后进入旧格式迁移 |
| 存在密钥、暂存密文或迁移进度，尚无已提交的 `store.enc` | 解锁并核对迁移进度，验证已完成目标后续迁；不直接宣布存储已就绪 |
| `store.enc` 已认证并标记新格式已提交 | 只按活动代际读取新格式，处理剩余清理任务 |
| 存在新格式痕迹但缺少密钥，或提交标记认证失败 | 报错并保留文件，不生成新主密钥覆盖，也不回退为明文读取 |

`store.enc` 是最后发布的提交点。发布前，旧文件仍是迁移源；发布后，新文件成为读取依据。
若已提交的新文件缺失或认证失败，应报告损坏，不能偷偷读取旁边的旧明文文件。
数据目录不允许旧版和新版同时使用；旧版不理解新锁，因此升级前必须停止所有使用该目录的旧进程。
新版本在整个生命周期持有数据目录锁，并在提交前复核迁移源指纹；锁与复核不能替代停掉不遵守锁的旧程序。

### 迁移流程

1. **盘点并冻结源。** 校验配置、会话及 shell 元数据，记录源文件长度、流式摘要和迁移格式版本。标识和摘要写入加密的 `state.enc`，进度界面只展示必要的计数。损坏配置、无 manifest 的孤立历史和不明临时副本必须报告，不能沿用旧加载器的“读不了就跳过”而宣称完整迁移。
2. **先持久化密钥。** 完成主密钥封装、文件同步及平台支持的目录持久化，并验证可重新解锁，再写业务密文。禁止先转换大量历史、最后才保存唯一的解密密钥。
3. **流式转换。** 将配置及历史写入 `.migration/<migration_id>/staging/`，只创建密文文件。日志按有限大小分块读取，内存使用不随总历史大小增长。进度记录事务 ID、目标文件 ID、源指纹以及每个单元的转换/验证/发布状态。
4. **验证完整单元。** 按 shell/配置单元完成同步、关闭与重新打开解密校验。未完成单元可以从头重建，重建时使用新的文件 ID 和随机 nonce；已经验证的单元复核后复用，不能无条件追加一遍历史。
5. **发布目标。** 将验证后的密文文件逐一发布到最终路径，完成所需同步。此时仍处于 MIGRATING；最终路径中出现密文文件不等于全局切换已经完成。
6. **原子提交。** 确认所有盘点到的必要单元均已转换、目标可读且源未变，再原子发布并持久化 `store.enc`。该提交点之前不删除源文件。
7. **清理并完成。** 仅清理已验证且与源指纹匹配的旧文件及已结束的迁移暂存。旧明文清理失败时标记 `CLEANUP_PENDING`，不能把“新格式已提交”展示为“全部数据已加密”。完成恢复后，历史会话按现有规则显示为 DEAD。

中断后的判断依据是认证过的进度和提交标记，并重新检查目标，而不是仅相信上次进度所写的“完成”。
磁盘空间不足、IO/Sync/重命名失败或 key provider 暂时不可用，都应保留可续迁状态和原始数据。
当前实现为保证独立校验与续迁，在提交前保留源、加密备份、暂存目标和已发布副本；迁移峰值高于仅复制一次旧数据，需预留充足空间。尚未实现磁盘空间预留或精确容量预检；实际写入、Sync 和发布失败会停止提交并保留源。完成后移除暂存，已转换配置的冗余备份也会清理。历史备份置于所属 session/shell 内，删除历史时一并移除。

### 旧历史的转换规则

- **输出字节不变。** 解密后所有 Output 正文按顺序拼接，必须逐字节等于旧 `log.bin`，保留 ANSI 控制序列、CRLF、非 UTF-8 字节和末尾半行。旧文件没有加密记录边界，不能按“看起来是不完整字符/转义序列”截掉尾部。
- **标记不能作为缓存丢弃。** `log.jsonl` 的状态、Unix 毫秒时间戳、偏移及同一偏移下的文件顺序必须保留，包括未知但格式合法的状态值。按偏移和原顺序合并，不能按时间戳重新排序。非法标记、越界偏移或残缺尾需要报告并保留原始证据，不能静默省略后认定无损。
- **流分类需要旧索引。** 根据有效的 `log.stdio` 切换点切分 Output 事件并写入来源。缺失或损坏时无法恢复真实 stdout/stderr 分类，需要明确报告其原有精度和降级情况；保持旧读取默认行为不代表证明原字节来自 stdout。
- **行索引重建。** 重新扫描正文中的 `\n`，生成新的行索引，再验证按行读取；旧 `log.lines` 缺失或损坏不应阻止输出字节的无损转换。
- **不补造事件。** 旧日志没有逐个输出块的精确时间，也没有完整 Resize 历史或原始 stdin。保留已有状态变更时间，将时间精度标为旧标记级或未知；按时间查询不能伪装成拥有新录制格式的精度。
- **标识和引用不变。** 保留 session ID、shell ID、主机名称和现有 shell 编号。老 manifest 若没有编号，沿用现有 `backfillShellIndexes` 规则，不能对已有编号重新排序或压缩空缺；会话地址和输出游标保持可用。
- **配置完整保留。** 不遗漏跳板链、代理、默认模式和审批规则；配置未知字段及必要的原始 TOML 可保存在加密容器中。内置覆盖读取失败时禁止回退成无审批默认配置。临时主机没有持久配置，不加入 `hosts.enc`，也不因迁移进入导出。

新索引能够完全重建的前提是：原有时间/来源/审批信息已经转入 `events.enc`。
只有正文转换成功而这些旧侧文件没有处理，不能算完整迁移。

### 验收、回退与明文清理

每个 shell 校验输出长度和流式摘要，并比较固定边界及跨记录随机窗口的 `ReadAt` 结果。
比较按行读取、stdout/stderr 过滤、所有合法标记、元数据、主机引用及 `termcp://#<session>:N` 定位行为。
配置迁移检查值和未知字段的完整性；必要时对原始配置做加密保存，避免仅按当前结构体重编码造成字段丢失。
明文文件不能获得事后真实性保证：迁移校验只能证明新旧数据一致，不能证明旧内容原本没有被修改。

提交前的失败保留旧源，可移除该事务拥有的未提交目标后重试；不能删除整个 session 目录，因为里面可能同时包含旧源和已发布的密文目标。
提交后禁止直接用旧二进制打开同一目录。若需要版本回退，应在独立数据目录恢复明确时间点的备份，迁移后的新增数据不能靠旧快照保留。
需要备份时使用加密备份，避免长期留存明文 `.bak`；清理应覆盖原配置、原 manifest、原日志、潜在敏感的旧运行日志，以及经盘点确认的敏感遗留副本。
普通删除不承诺擦除 SSD、文件系统快照或外部备份中的历史明文；迁移完成声明的范围必须明确。

强制验证场景包括：纯旧目录、空历史、多 shell、空缺编号、缺失行索引、同偏移多标记、非 UTF-8/CRLF/末尾半行、丢失流索引、非法元数据，以及只有元数据没有输出的 shell。
在每个转换/同步/发布/提交/清理边界注入崩溃或 IO 故障，重复启动必须不漏历史、不重复导入、不错误回退明文。
还要覆盖密钥丢失、错误密码、源变化、磁盘耗尽、旧文件删不掉、迁移中断后再次切换 provider，以及 Windows 句柄占用导致的替换失败。
用户提示验收还须覆盖：首次迁移、续迁、盘点尚未完成、磁盘空间不足、解锁失败、成功但清理未完成、正常完成，以及无迁移的普通重启。
至少核对 Web UI、前台 CLI、daemon 启动入口及 MCP stdio 的协议纯净性；运行时提示与该版本 Release 中承诺的行为必须一致。

## 接入与验证顺序

1. KeyManager、文件格式与密钥封装，确定 key slot、版本、AAD 和恢复边界。
2. EncryptedAppendFile 的独立记录、短写处理、并发读取与逻辑偏移，验证内存发布和 Sync 的区别。
3. 可重建的加密索引，覆盖按字节、按行、按时间和 stdout/stderr 分类读取。
4. 崩溃恢复测试：子进程强制终止、每个记录边界的截断、完整密文损坏、索引丢失/超前、Sync 故障注入、恢复后继续追加。强制终止不等于真实断电，持久化顺序还需要故障注入验证。
5. 接入 `internal/storage`、`internal/message`、`internal/sshconfig` 和启动流程，再接入 Web UI 解锁；保留现有 shell_id、输出偏移和审批语义。
6. 按上述迁移协议交付旧格式检测、停写转换、解密比对、事务提交、中断续迁和明文清理。配置导出和诊断日志独立处理，防止绕开加密边界。该项是启用新格式的前置条件，不作为上线后的补充功能。

各阶段测试必须适配 Windows/macOS/Linux，遵循 [`testing.md`](../agents/testing.md)，并在文件系统及生命周期相关修改后运行压力测试。
