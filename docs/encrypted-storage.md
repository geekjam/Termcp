# 加密存储、解锁和旧文件升级

服务端使用纯文件存储：XChaCha20-Poly1305 追加记录、加密配置与元数据、可重建的加密索引。不需要 SQLite、FUSE 或额外数据库。
这是开发分支的行为；首次启用该功能的 Release 必须包含本页的升级注意事项。

## 首次设置与密码修改

默认采用系统密钥托管：首次启动生成随机数据主密钥，使用当前系统账户的 DPAPI、Keychain 或 Secret Service 保护，后续启动自动解锁，无需每次输入密码。提供非空 `TERMCP_STORAGE_KEK` 时优先使用 ENV 托管，适合容器和无桌面服务器。

主密码为可选恢复方式。打开 `storage.html`（配置了 HTTP 认证时先登录），输入两次相同的主密码，为已解锁的托管存储增加 Argon2id 密码封装；保留原数据主密钥和自动解锁方式。用户输入的密码不是数据主密钥。系统托管不可用且没有 ENV 时，也可用该表单初始化密码存储，界面会提示重启仍需密码。

已有仅密码存储升级后，在尚未显式保存手动方式且默认采用自动方式时，需要输入原密码成功解锁一次，才可安全增加系统或 ENV 托管；此后自动启动。不可用的托管服务不会导致明文密钥落盘或覆盖旧数据。
自动或手动解锁后，先完成迁移及历史恢复，再开放工作区、SSH 会话和 MCP。业务请求在此之前返回 503 和明确的存储状态。
后台 daemon 的空闲倒计时在业务就绪后才开始，等待用户解锁和迁移期间不计时。
MCP stdio 的 stdout 仍只输出协议消息；存储未就绪时，桥接返回协议错误及存储状态。人工解锁后重新连接 MCP 客户端。
使用无 Web UI 的构建时，可通过下列 REST 接口或 ENV/系统托管模式操作。

工作区的「加密存储」页提供「解锁方式」选择框：默认自动解锁，也可选择「每次重启输入主密码」并保存。修改方式仅在存储就绪后允许，当前运行保持解锁；浏览器刷新不会锁定服务。
切换时，已有主密码需再次验证当前密码；未设置主密码而选择手动方式时，必须输入并确认新的主密码。手动方式会移除所有自动解锁 slot；选择及密码封装在同一个 `master.key` 中原子保存，之后即使 ENV KEK 或系统托管仍可用，每次服务重启也要手动解锁，成功输入密码后不会重新自动托管。
切回自动方式时先验证当前主密码，并验证所配置的系统/ENV provider 可用后再保存；失败时保留原方式。Web UI 已保存的方式优先于 `TERMCP_STORAGE_KEY_PROVIDER` / ENV 的默认启动选择；自动方式内部仍以非空 ENV KEK 优先。旧版没有显式选择的密钥封装继续沿用原有默认行为。

工作区的「加密存储」入口也用于修改密码。必须输入当前主密码、新主密码及确认新主密码；后端会再次验证当前密码。
改密仅重新封装主密钥，不重写历史数据。只有密钥文件持久化确认后才返回成功；若提示持久化未确认，保留旧、新密码，排除文件系统问题后重启验证。
浏览器退出登录或关闭页面不会锁定运行中的存储；没有运行期间主动锁定功能。

密码只出现在表单和 JSON 请求体中，不写入 URL、日志、localStorage 或 sessionStorage。
远程提交密码使用 HTTPS。反向代理应明确配置 `TERMCP_STORAGE_TRUSTED_PROXIES`，值为逗号分隔的代理来源 CIDR，并由该可信代理覆盖设置 `X-Forwarded-Proto: https`。
未配置可信代理时，不接受远程客户端自行提供的转发头；本机 loopback 请求可使用 HTTP。
存储密码与 `TERMCP_AUTH_TOKEN` / `TERMCP_AUTH_HASH` 独立，不能互相替代。

## 无人值守解锁

| 选择 | 配置 | 行为 |
| --- | --- | --- |
| 系统托管（默认） | 不设置 provider，或 `TERMCP_STORAGE_KEY_PROVIDER=system` | 首次自动初始化，后续自动解锁；可选设置恢复主密码 |
| Windows DPAPI | 默认系统托管 | 随机 KEK 由当前 Windows 账户保护，文件内仅保存 DPAPI 密文 |
| macOS Keychain | 默认系统托管 | 使用当前登录 Keychain；系统可能要求授权访问 |
| Linux Secret Service | 默认系统托管 | 需要桌面 Secret Service 与 libsecret 的 `secret-tool` |
| 容器/服务器 ENV | 提供 `TERMCP_STORAGE_KEK`；可明确设置 `TERMCP_STORAGE_KEY_PROVIDER=env` | 严格 Base64 编码的随机 32 字节 KEK；首次自动初始化，后续自动解锁；可选设置恢复主密码 |
| 手动密码 | 明确设置 `TERMCP_STORAGE_KEY_PROVIDER=password` 且不提供 ENV KEK | Web UI/API 首次设置；每次启动手动解锁 |

显式提供非空 `TERMCP_STORAGE_KEK` 时优先尝试该 ENV provider。KEK 不会写回数据目录；不要把它与加密数据放在同一个未受保护的备份中。无桌面 Linux 和 Docker 应配置 ENV KEK，以便无人值守重启。
默认系统托管不生成预设密码。已通过系统或 ENV 解锁的 READY/CLEANUP_PENDING 存储，可通过初始化密码接口增加第一个密码 slot；已有密码之后只能通过当前密码验证修改。设置和修改主密码都保留自动解锁 slot，不重新加密历史。
自动方式下，已有密码存储在首次成功手动解锁后，会保存所配置的自动解锁 slot；已保存手动方式则不会托管。托管失败时保留密码及历史可用，API 的 `auto_unlock_error`、Web UI 和日志提示下次启动需密码；未确认密钥文件持久化时返回 `key_save_uncertain`，不能报告托管成功。
provider 不可用、密码错误或主密钥文件丢失时，不能生成新密钥覆盖既有数据。托管凭据丢失后，存储保持 LOCKED；可恢复原托管方式，或使用已设置的主密码解锁并重新建立托管。
保存解锁方式后，密钥封装升级为带认证启动策略的版本 2；旧版本 1 仍可读取，历史和配置密文格式保持不变。不能用不支持版本 2 的旧二进制打开已保存选择的目录。
跨账户或跨机器移动数据时，系统托管凭据可能不再可用；只复制 `master.key` 不等于复制了系统凭据。可提前设置恢复主密码，备份完整数据目录和相应的解锁方式。

## 升级迁移

1. 停止所有使用相同数据目录的旧版进程，备份完整数据目录，并保护可能包含秘密的旧备份。旧版不遵守新目录锁，不能与新版同时运行。
2. 为旧源、加密备份、暂存及最终密文预留充足空间。当前没有精确容量预检或空间预留；空间不足会停止迁移并保留源。
3. 启动后默认自动托管并解锁密钥，随后开始迁移；已有仅密码存储先输入原密码一次。Web UI 持续显示首次迁移/续迁提示、阶段、文件/单元数及转换字节数；阶段日志不包含主机凭据和原始输出。
4. 提交 `store.enc` 前验证配置、原始输出、标记和来源索引；提交成功后才清理原文件。中断后用相同密钥重启，复核已完成密文后继续。
5. 若显示 `CLEANUP_PENDING`，加密业务存储已可用，但仍有旧明文未清理。检查文件占用、权限和源文件是否被旧进程修改，再重启重试；未完成清理前不要宣称所有本地数据都已加密。

会话 ID、shell 编号、按字节/按行读取及 stdout/stderr 分类保持兼容，历史会话按重启规则恢复为 DEAD。
缺失旧 `log.stdio` 时沿用旧版默认 stdout，不能由此推断原始输出来源；旧输出只有标记级时间，没有逐块精确时间、Resize 或原始 stdin，不补造这些信息。
损坏元数据、孤立历史、非法或残缺标记、源文件变化会阻止提交并保留源，需修复后重试。

新业务路径为 `keys/master.key`、`config/hosts.enc`、`sessions/<session_id>/meta.enc`、`sessions/<session_id>/<shell_id>/{meta.enc,events.enc,events.idx.enc}`。
`store.enc` 是认证加密的提交标记；`.store.lock` 是不含秘密的系统锁文件。
迁移中间文件从首次写入起即为密文；任务清单位于 `.migration/active/state.enc`。会话相关的迁移副本放在所属会话/shell 的 `.legacy-<id>/` 中，删除历史时一并删除。
旧诊断和其他遗留副本位于 `diagnostics/legacy-<id>/`；正常完成后删除暂存及已转换配置的冗余备份。

迁移后不要用旧二进制打开同一目录。需要回退时，在独立目录恢复升级前备份；旧快照没有升级后新增的数据。
新格式备份需包含完整目录和对应的解锁方式，丢失数据主密钥无法恢复历史。
文件系统路径、文件长度和时间仍可见；迁移会清理空的旧主机命名目录，但包含无关用户文件的目录和需保留的遗留副本路径可能仍显示旧名称。用户主动导出的配置可选择独立文件密码；不设密码时仍是含凭据的明文 TOML。文件传输目标保留原始文件格式。临时主机不持久化、不参与导出。
新的 `termcp.log` 仅记录过滤后的运行诊断；旧敏感诊断先转换为密文再清理。普通删除不承诺擦除 SSD、快照或外部备份中的旧明文。

## 配置导入与导出的文件密码

工作区的「导出配置」会显示可选文件密码及确认框。两项均留空，下载原有的 `termcp-connections.toml` 明文文件；填写相同密码则下载 `termcp-connections.toml.enc`。明文导出包含主机凭据，界面会持续提示这一点。临时主机仍不参与任何导出。

文件密码独立于存储主密码，服务端不保存它。加密文件使用随机 salt、Argon2id 和随机 nonce 的 XChaCha20-Poly1305，可以在另一台 Termcp 实例中导入，不需要原实例的主密钥。不要遗忘文件密码；源实例仍保存其原配置。

「导入配置」接受 TOML 或加密文件，并提供解密密码输入框。明文文件留空，加密文件输入导出时设置的密码。服务端按内容识别格式，完整验证认证标签后才导入；错误密码、损坏文件和无效配置不会部分导入。重名自动改名和临时主机选项保持原有规则。

密码只通过请求体提交，不出现在 URL、日志或浏览器持久存储。上传及解密均在内存进行，不生成明文临时文件。新接口为 `POST /api/connections/batch/export`（JSON）和 `POST /api/connections/batch/import`（multipart）；原有明文 GET 导出和原始 TOML POST 导入继续可用。协议字段见 [HTTP API](api.md)。

## 持久化与损坏恢复

每个输出记录独立认证，公开输出偏移仅计算原始输出字节。运行中可以读取完整写入的历史，无需关闭会话。
默认每 1 秒或累计 256 KiB 执行 Sync，显式同步和正常关闭也会同步；这不承诺突然断电时固定最多丢失一秒。
重启只接受通过认证的完整记录；不完整最终框架先保存完整密文副本再恢复有效前缀，完整记录认证失败则停止，不自动截断。
索引是缓存，缺失、损坏或过期时从权威事件日志重建。当前启动仍扫描日志，底层记录引用及行/标记视图占用的内存随历史规模增长。
强制终止和 IO 故障测试不能替代真实断电验证；整段有效尾部删除或完整数据回滚需要外部可信检查点才能检测。

接口字段见 [主密码 API](design/storage-password-api.md)，格式见 [加密文件格式](design/encrypted-file-format.md)，发布提醒见 [Release 草稿](release-notes/encrypted-storage-migration.md)。
