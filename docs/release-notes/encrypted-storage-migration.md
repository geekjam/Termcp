# 加密存储迁移：Release 升级提示草稿

状态：开发分支已实现迁移及运行时提示；发布前需完成跨平台 CI 和升级验收。
本文件不是已发布的版本说明，不绑定版本号，也不触发发布。

首次启用迁移时，将下面的“升级必读”正文置于对应版本 `CHANGELOG.md` 的功能列表之前。
发布前按实际行为复核迁移时机、提示、备份、清理及回退说明；不能仅发布这段文案而缺少运行时提示。

### 升级必读：新版本会迁移旧持久化文件

- **本版本首次启动检测到旧格式后，会在完成密钥设置或解锁后，将旧持久化文件迁移为加密格式。** 迁移范围包括持久主机配置、扩展模板（含 HTTP 认证头）、会话与 shell 元数据、终端历史及其索引。临时主机仍只保存在内存中，不参与配置迁移或导出。
- 默认使用系统托管，首次启动自动生成并保护密钥，后续无需输入密码；容器/无桌面环境配置 `TERMCP_STORAGE_KEK`。可在 Web UI 设置恢复主密码；已有仅密码存储需成功手动解锁一次来建立自动托管。托管不可用时界面会提示，不能静默保存明文密钥。
- **升级前停止所有使用同一数据目录的旧版 Termcp 进程，并备份完整数据目录。** 默认目录为 `~/.termcp`；使用 `--data-dir` 或 `TERMCP_DATA_DIR` 时，以实际配置的目录为准。备份也可能包含明文凭据和终端历史，应加密或妥善保护。
- 迁移时会同时保留旧源、加密备份、暂存及发布的密文目标，请预留充足额外磁盘空间；目前不预留空间，写入失败后停止提交。历史较多时首次启动可能较久；迁移期间暂不接受会话操作，Web UI 和启动日志会提示当前阶段、续迁及进度。
- 旧文件在目标数据转换、校验及提交成功前保留。进程中断后，下次启动会检查已有进度并续迁；遇到损坏、磁盘空间不足或解锁失败时会给出提示，不会把旧数据直接覆盖成空存储。
- 已有加密存储中的旧扩展模板会追加迁移，保留原有主机和历史；模板未知 TOML 字段也按原始字节保留。
- 迁移完成后，原有会话 ID、shell 编号、历史输出偏移和行号保持兼容。历史会话按原有重启规则作为已结束会话查看，不自动恢复原来的进程。旧记录缺少的精确时间或终端尺寸变化历史不会被补造。
- 如果新格式已经提交，但旧明文文件清理失败，会明确提示仍有明文残留。只有完成清理后才会显示迁移全部完成；需要保留的备份应使用加密形式。
- **迁移后不要直接用旧版程序打开同一数据目录。** 如需回退，在独立目录恢复升级前的备份；旧快照不包含升级后新增的数据。迁移后的备份需要包含密钥封装文件，并保留相应的解锁方式。
